# 3D监视器 node-spread 分支问题诊断 + 优化策略

## 测试数据
CodeGraph 项目扫描结果：254 节点、760 连接

## 问题诊断

### 问题1：单层节点过载
```
presentation: 141 个（55%）→ 全部挤在同一 Y 层
infrastructure: 85 个（33%）
external: 17 个
business: 11 个
```
141 个节点在同一个 Y 层，X/Z 轴被迫拉得很宽 → 「一堆一堆隔得远，要拖拽找来找去」

### 问题2：Y轴分层与数据不匹配
当前 5 层是写死的（infrastructure/data/business/presentation/external），但扫描结果只有 4 层有数据，且分布极不均匀。

### 问题3：连线穿模仍然存在
760 条连接，障碍规避 maxIter=18 勉强够，但大密度场景下仍有穿透。

### 问题4：力导向分支未充分利用
force-layout 分支用连接驱动布局，理论上能自动把密集连接的节点聚在一起，但未与当前扫描数据配合测试。

## 优化策略

### 策略A：动态层数 + 子层折叠
- 每个 layer 内根据节点数量**自动分多个子层**（sub-row）
- 超过 20 个节点的 layer 自动拆成多行，用 Z 轴错开
- 同 layer 节点聚集在一个区域，不拉宽 X 轴

### 策略B：混合布局
- layer 决定 Y 轴（层级感）
- 同 layer 内用 force-directed 决定 X/Z（避免手动排布）
- 在 node-spread 分支上引入 force-layout 的力导向算法

### 策略C：自适应镜头 + 分组折叠
- 自动检测节点分布，调整初始 camera 位置使所有节点可见
- 同 layer 超过 30 个节点自动启用「组折叠」
- 点击组展开，其他组半透明

### 策略D：图例交互
- 点击 layer 名→只显示该 layer 的节点（过滤）
- 双击节点→聚焦到该节点及其一级连接
