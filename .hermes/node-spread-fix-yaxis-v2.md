# Y 轴改为参考+自然散布（v0.1.42-spread 修复）

## 问题
当前 viewer.html 中节点驱动模式（node-driven）的 Y 轴处理：
- 同一层级的所有节点都在同一个精确 Y 值上（y=0 或 y=1 等）
- Codex 尝试加了 ±0.15 的随机微调，但幅度太小，肉眼看不出变化

## 根因
`computeLayout` 中，Y 轴被写死了：`yPos = LAYERS[layerKey].y`，所有同一层级的节点共用一个 Y 值。

## 正确做法
跟 X 轴一样——X 轴的做法是：同组内每个节点按顺序有自己独立的 X 位置，不是全部挤在同一点上。

Y 轴也应如此：同层级内每个节点在 Y 方向上有自己独立的散布位置。

### 具体改动

将 viewer.html 中 computeLayout 函数的节点驱动模式（约 2900-3000 行区域），修改 Y 轴计算逻辑：

**找到 Y 轴赋值的地方（大概是 `yPos = LAYERS[lk].y` 或类似），改为：**

```javascript
// Y 轴：层级参考 + 基于节点次序的自然散布
// 原理：同一层级内，每个节点按它在层内的排列次序在 Y 方向上自然错开
// 排在前面的节点 Y 稍高，排在后面的节点 Y 稍低（或相反），形成立体层次
var yRef = LAYERS[lk] ? LAYERS[lk].y : 0;
// 根据节点在层内的索引，在 Y 上自然散布
// 每个节点 Y = 参考值 + (节点索引 / 该层节点总数 - 0.5) * 散布幅度
var count = bucket.length;
var ySpread = 0.6; // 散布幅度：让同一层节点的 Y 有 ±0.3 的差异
var nY = yRef + (index / count - 0.5) * ySpread * 2;
```

这个跟 X 轴的做法一致：X 轴也是按顺序排列，每个节点有自己独立的 X 位置。

或者更灵活的方式：让 Y 与 X 位置关联，形成自然的立体倾斜：
```javascript
var nY = yRef + (posX / maxX) * 0.4;
```

### 验收标准
- 同一层级的节点不再全部挤在同一水平面上
- 从侧面看，节点在 Y 方向上有自然的散布（能看到层内节点的高低差异）
- Y 轴整体仍能看出层级参考关系（基础设施层在下方，展示层在上方）
- 0 JS 报错
