# 架构展示分层方案 — 从技术模块到功能架构

## 背景
主公提出的核心洞察：3D图展示太偏技术模块（port-tag-tool按目录分），不懂技术的人看不懂。

## 三级架构视图
```
功能架构层级  ← 默认视图，业务语言
   ↓ 双击
技术模块层级  ← 当前视图（按目录/依赖分组）
   ↓ 双击
文件节点层级  ← 细节视图
```

### 功能架构是什么？
对 Hermes Agent 来说，功能模块不是 `acp_adapter`、`agent-lsp`，而是：
- **调度中心（Orchestrator）** — Kanban调度、任务派发、轮询
- **研究部（Research）** — 行业分析、数据采集、信号检测
- **风控部（Risk）** — 成本追踪、异常检测、合规检查
- **系统部（System）** — Codex CLI调度、仓库维护
- **知识管理（Knowledge）** — Obsidian归档、PLUR记忆
- **内容运营（Operations）** — 内容生产、社交媒体、日报

每个功能模块对应多个技术模块（packages/directories）。

## 但当前做什么
短期内无法实现三级视图（重构量太大）。
**当前建议**：不改变展示形式，但给聚合节点加**功能标签**，让用户知道这个技术模块属于哪个功能模块。

示例：
- `agent` 模块 → 标注 "功能：调度中心"
- `kanban` 模块 → 标注 "功能：调度中心"
- `plugins` 模块 → 标注 "功能：系统部"

这样在现有的技术模块视图上，叠加功能分类的视觉提示。
