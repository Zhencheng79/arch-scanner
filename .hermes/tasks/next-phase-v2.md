## 议题一：模块详情面板（目标9+）

### 交互设计

**触发方式**：
- 点击模块台面 → 弹出模块详情面板
- 点击模块标签 → 弹出模块详情面板
- 点击模块内节点 → 弹出节点详情（与现有行为一致）
- **点击空白区域** → 隐藏详情面板

**面板内容**：

```
┌─ 模块详情 ─────────────────────────┐
│ [← 返回] 模块名称: components        │
│                                      │
│ 📊 统计                              │
│   成员节点: 10                       │
│   层级分布: presentation(6) business(4)│
│   连接数: 28（模块内12，模块间16）      │
│                                      │
│ 📁 成员节点（单击跳转节点详情）         │
│   □ AccordionExpand                 │
│   □ BillboardText                   │
│   □ ConnectionLine                  │
│   ...                               │
│                                      │
│ 🔗 模块间连接                        │
│   → data（5条data流, 2条control流）   │
│   → packages-port-tag-tool（3条data）│
│   ← .hermes（2条data流）             │
└──────────────────────────────────────┘
```

**导航行为**：
- 点击"← 返回" → 回到之前查看的面板（可能是节点详情）
- 点击成员节点列表中的节点 → 切换到该节点的详情面板
- 按ESC键 → 关闭面板

**实现**：复用现有nodeInfoPanel的DOM结构，增加"模块模式"切换。

## 议题二：模块排布策略（目标9+）

### 量化规则

| 参数 | 公式 | 示例（4模块） | 示例（12模块） |
|------|------|:------------:|:-------------:|
| 台面间距 | `模块数×0.3+2` | 3.2 | 5.6 |
| 台面宽度上限 | `max(单个宽度, 20)` | 20 | 12 |
| 每行最大宽度 | `min(视口宽, 120)` | 80 | 80 |
| 折叠阈值 | 模块数≥10 | 不折叠 | 折叠 |

### 排序策略

模块按照**连接数降序**排列（连接多的模块优先靠左/靠上）：
```
computeModuleOrder(modules) → sort by totalConnections desc
```

### 多行换行（已有）

当前代码已有 `MULTI_ROW` 换行逻辑，保持。

### 折叠模式（兜底）

当模块数≥10时：
- 默认折叠，台面只显示模块名+成员数
- 双击模块标签展开显示内部节点
- 当前4个模块不触发

## 议题三：CodeGraph 参考（目标9+）

### 优先级路径

| 优先级 | 内容 | 预估 | 说明 |
|:-----:|------|:----:|------|
| P0 | **改进 detectModule**：借鉴CodeGraph的目录前缀分组，增加框架特征文件识别（如检测到`setup.py`→Python模块） | 1天 | 低风险，直接收益 |
| P1 | **框架路由识别**：解析导入语句，匹配17个框架的特征库，给节点打框架标签 | 2天 | 需要调研框架特征 |
| P2 | **增量扫描**：参考CodeGraph的FSEvents监听机制 | 3天 | 依赖P0的模块检测稳定 |

### 直接调用的可能性

CodeGraph 提供 MCP 工具（8个），理论上可以：
```
CodeGraph MCP → scan → JSON → arch-scanner MCP → 3D渲染
```

但：
- CodeGraph的JSON输出和我们port-tag-tool的JSON schema不同，需要适配层
- CodeGraph的模块命名规则和我们不同，需要映射
- **不建议**：会增加依赖链（CodeGraph需要单独安装和运行）

**建议做法**：只借鉴思路和算法，不直接调用CodeGraph的MCP。

### 框架路由识别实施路径

1. 在 port-tag-tool 中添加框架特征文件检测：
   - `setup.py` / `pyproject.toml` → Python/FastAPI/Django
   - `package.json` dependencies → React/Express/Vue
   - `Cargo.toml` → Rust
   - `go.mod` → Go
2. 给匹配的节点添加框架标签（如 `framework:fastapi`）
3. 在3D视图中用特殊图标或颜色标记框架节点
