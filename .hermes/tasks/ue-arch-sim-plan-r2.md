> 综合赵公明初案 + 军师审阅意见
> 审阅评分: 6.5/10
> 审阅人: strategist
> 时间: 2026-06-20

## 一、战略意图（保留原方案精华）

**一句话定位**：
> arch-scanner（port-tag-tool + 3d-monitor）负责"扫和轻量看"（浏览器秒级），UE 架构模拟器负责"沉浸式玩"（需安装，分钟级）。两者数据同源、渲染分离、场景互补。

**核心原则**：
1. arch-scanner 的浏览器即用体验是底线，不能动
2. UE 方案是增值扩展，不是替代
3. port-tag-tool 输出的 JSON（`{nodes, connections, ports, tags}`）是共享数据源

## 二、军师指出的 4 个关键盲区（已采纳并修正）

### 盲区 1：macOS UE 兼容性未验证 ⚠️ **关键风险**

**原方案遗漏**：默认 UE 5.8 在 macOS 上能跑数据桥接脚本。

**实际状况**：
- UE 5.x 在 macOS 上**已弃用 Python 脚本编辑器**（Python Editor Script Plugin 在 5.4+ 不再官方支持）
- 替代方案：蓝图、C++ 插件、或 **MCP 远程调用**
- 另外，iMac 的 Radeon Pro 580X 仅支持 Metal 2，Lumen/Nanite 在 macOS 不可用

**修正方案**：阶段1的数据桥接路径改为：
```
❌ UE Python脚本读JSON
✅ Hermes MCP → UE MCP（通过 MCP 协议逐条创建 Actor）
  或
✅ 写一个 UE C++ 插件，通过 JSON 批量导入场景
```

### 盲区 2：Pixel Streaming 复杂度被低估 ⚠️

**原方案**："通过 Pixel Streaming 把场景推送到浏览器"

**实际**：
- Pixel Streaming 需要**专用 GPU 服务器**（macOS 不支持作为 Pixel Streaming 服务器）
- 需要 TURN/STUN 服务器用于网络穿透
- 延迟和带宽要求高
- iMac 无法做 Pixel Streaming 服务端

**修正方案**：
- 阶段3的"多人评审"改为：**录屏分享 / UE Editor 远程桌面（Parsec）**
- Pixel Streaming 标记为"将来迁移到 PC 后再评估"

### 盲区 3：MCP Plugin 自建工作量被隐藏 ⚠️

**原方案**：阶段4"MCP 互联"仅描述了结果，没算建造它需要的成本。

**实际**：
- Unreal MCP 官方插件是通用 MCP 服务，只暴露基础的编辑器操控工具（create actor, modify 等）
- 要实现"加载 JSON 架构图"这个高级功能，要么在 UE 端写 C++ 插件扩展 MCP 工具集，要么通过 Hermes 逐条调用基础 MCP 工具
- 逐条调用效率极低（一个 50 节点的图需要 50+ 次 MCP 调用）

**修正方案**：
- 阶段4提前到阶段1：**优先开发 UE MCP 批量 Actor 生成工具**（C++ 插件）
- 或直接在 UE 端写一个独立的工具（蓝图库），暴露单个 MCP 端点 `load_architecture_graph(json_data)`

### 盲区 4：3d-monitor 未稳定前不应启动 UE 开发 ⚠️ **顺序问题**

**军师核心建议**：在 3d-monitor 稳定化前，UE 方案保持技术预研定位，先花 2 人天做 macOS 兼容性验证 + POC。

**采纳**：调整优先级排序。

## 三、修订后的分阶段方案（v1.1）

### 第0步：技术预研（1-2天，现在可开始）

**目的**：回答"macOS UE 5.8 究竟能不能做这件事"，而非直接承诺产品化。

| 子任务 | 内容 | 预计 |
|--------|------|------|
| 0.1 | 安装 UE 5.8（后台下载） | ~2-4h |
| 0.2 | 创建空白项目，启 Unreal MCP 插件 | ~15min |
| 0.3 | Hermes 连接 UE MCP，测试基础操控（create actor） | ~5min |
| 0.4 | **POC**：通过多次 MCP 调用，在 UE 场景中手动还原一个 5 节点的小项目结构 | ~2-4h |
| 0.5 | 记录兼容性结论 → 决定是否进入阶段1 | — |

**可交付**：一份 macOS UE 5.8 MCP 兼容性报告 + 5 节点 POC 场景。

### 第一步：3d-monitor 稳定化（当前项目优先）

**这是军师强调的前置条件。**

| 任务 | 说明 |
|------|------|
| 完成 node-spread 剩余问题 | 台面/箭头/面板已在 v.19 修复，持续测试 |
| 同步 force-layout 分支 | feature/force-layout 落后 9 个版本 |
| 代码质量 | 750KB 单文件 → 考虑代码分割 |
| 验收五问 | 确保两个分支读出同样的架构结论 |

**完成标准**：3d-monitor 在 node-spread 和 force-layout 两分支都稳定通过验收五问。

### 第二步：UE MCP 批量数据导入工具（C++ 插件）

**做在 UE 端的核心基建，后续所有功能依赖它。**

- 编写 UE C++ 插件 `ArchImporter`
- 功能：接收 JSON → 批量创建 Actor + 连接线 + 标签
- MCP 端点：`load_architecture_graph(json_path)` / `load_architecture_graph_from_string(json_string)`
- 参考 Unreal MCP 官方 Plugin 源码（C++，开源）

**注意**：因为 macOS 不支持 Python 脚本，这条路（C++ 插件）是唯一选择。

### 第三步：基础交互（基于 UE MCP 已有工具）

- 单击高亮 + 详情显示（UE MCP 的 SceneQuery 能力）
- 搜索定位（UE 控制台命令）
- 层级显示/隐藏（通过 Unreal MCP 的 Visibility 控制）

**不需要额外插件，直接用 Unreal MCP 官方工具。**

### 第四步：动态模拟（UE 独有价值区）

**仅当前三步完成后评估是否进入。**

- 连接线流动光效（UE Niagara 粒子系统）
- 热力图模式
- 故障注入演示
- **评审场景**：录屏分享 / Parsec 远程桌面（放弃 Pixel Streaming）

## 四、时间线估算（修订版）

```
第0步 技术预研       ───── 1-2天（现在）
                          │
第1步 3d-monitor稳定化  ───── 当前项目冲刺（1-2周）
                          │  ← 决策门槛：3d-monitor稳定后
第2步 UE MCP插件       ───── 3-5天
                          │  ← 决策门槛：POC成功 + 硬件够用
第3步 基础交互         ───── 2-3天  
                          │  ← 决策门槛：插件可用
第4步 动态模拟         ───── 4-8天（可选，先做1-2个场景）
```

**总计：技术预研 2 天 + 核心开发 8-16 天**

## 五、决策树（简洁版）

```
现在
  └── UE 技术预研（第0步）→ 安装 + POC
        │
        ├── POC 成功 + 体验可接受
        │     └── 等 3d-monitor 稳定化 → 启动 UE MCP 插件开发
        │
        └── POC 失败（卡顿/不可用/无法实现）
              └── 放弃 UE 路线，arch-scanner 专注 Three.js 优化
```

**不需要现在就决定是否投入全面开发。先花 1-2 天装 UE + 做 POC，有了真实体感再决策。**
