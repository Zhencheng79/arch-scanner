## 一、AGENTS.md 修改提案（统一版）

> 将 AGENTS.md 第26行：
> ```
> - viewer.html 是单文件，所有代码内联，不要拆分成多文件
> ```
> 改为：
> ```
> - viewer.html 是核心渲染文件，所有 Three.js 场景代码内联。CSS 和独立 UI 层（图例/面板/提示框）可拆分到同目录下的辅助文件，入口保持 viewer.html 不变。
> ```

**理由**：viewer.html 已从~200KB 增长到 756KB。CSS+UI层抽出后入口降至~200KB，不影响离线可用性，不触及 Three.js 核心渲染逻辑。

## 二、执行顺序（重构版）

### 核心思路：同步 → 锁定 → 独立拆分 + 验证

```
Phase A：同步功能（单文件，纯功能对齐）
  force-layout 赶上 node-spread（v.13→v.20）
  ↓
Phase B：锁定功能一致
  扫描两个测试项目，对比量化指标，截图存档作为基准线
  ↓
Phase C：独立拆分（两分支各自进行，不交叉覆盖）
  ├── node-spread 分支：拆出 CSS + UI层 + layout-engine
  └── force-layout 分支：应用同样的拆分结构（手动做，非复制覆盖）
        ↓
Phase D：最终验收
  两个分支各自在拆分后的结构上运行，验证功能一致
```

**关键设计**：Phase C 中两分支各自应用拆分，不是"从 node-spread 复制到 force-layout"，而是"以同样的拆分方案在各自分支上手工拆分"。这样 force-layout 的力导向逻辑在拆分时就被正确保留。

## 三、详细执行步骤（含人天估算）

### Phase A：force-layout 功能同步（8天）

在**单文件 viewer.html** 上操作，不做结构变化。

| 子任务 | 内容 | 关键逻辑 | 预估 |
|--------|------|---------|:----:|
| A1 | **基准验证**：确认 force-layout 当前渲染正常，截图存档 | 记录节点/连线/模块数 | 0.5天 |
| A2 | **适配v.13**：箭头加粗 + 模块标签 + 详情面板 + 配色统一 | TubeGeometry参数 + CSS2D标签 | 1天 |
| A3 | **适配v.14**：恢复层配色 + 模块色边框辅助 | LAYER_CONFIG覆盖 | 0.5天 |
| A4 | **适配v.16**：修复 module Y 位置偏移 | 力导向Y轴计算调整 | 1天 |
| A5 | **适配v.17**：buildScene 补全 detectModule() | node.module赋值 | 0.5天 |
| A6 | **适配v.18**：computeLayout 全局模块扫描 | **最大难点**：力导向聚类适配 | 2天 |
| A7 | **适配v.19**：动态detectModule + 台面 + 箭头 + 面板 | 台面在力导向上的适配 | 1.5天 |
| A8 | **适配v.20**：穿模检测(maxIter) + 图例多类型 | 穿模检测逻辑通用 | 1天 |
| | **Phase A 小计** | | **8天** |

### Phase B：锁定功能一致（1天）

| 子任务 | 内容 | 预估 |
|--------|------|:----:|
| B1 | 用 port-tag-tool 扫描 arch-scanner 自身 | 0.25天 |
| B2 | 用 port-tag-tool 扫描 hermes-web | 0.25天 |
| B3 | 在两个分支上分别渲染，填写量化对比表，截图存档 | 0.5天 |

**产出**：一份"双分支基准对照表"，作为后续拆分的验证基准。

### Phase C：独立代码拆分（两分支各2天 = 4天）

**策略**：两分支各自做拆分，不是"复制后合并"。先从 node-spread 摸索拆分方案，然后在 force-layout 上手动复现。

| 子任务 | 内容 | 分支 | 预估 |
|--------|------|:----:|:----:|
| C1 | CSS 抽离 → `styles.css`（纯样式搬迁） | **node-spread** | 0.5天 |
| C2 | UI层抽离 → `ui-layer.js`（图例/面板/tooltip等） | **node-spread** | 1天 |
| C3 | 布局引擎抽离 → `layout-engine.js`（computeLayout+模块检测） | **node-spread** | 1.5天 |
| C4 | 在 force-layout 上应用同样的拆分 | **force-layout** | 2天* |
| | **Phase C 小计** | | **5天** |

> *C4 时间比 C1-C3 合计多，因为需要排查两分支的 computeLayout 差异（力导向 vs Y轴分层），确保拆分时不出错。

### Phase D：最终验收（1天）

| 子任务 | 内容 | 预估 |
|--------|------|:----:|
| D1 | 两个分支各自加载两个项目 | 0.25天 |
| D2 | 填写量化对比表，与 Phase B 的基准线对比 | 0.5天 |
| D3 | 验收五问检查 + 截图对比 | 0.25天 |

**总量：8 + 1 + 5 + 1 = 15 天**
