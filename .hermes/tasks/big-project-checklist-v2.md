# 大项目3D图验收清单 v2

## 背景
Hermes Agent（3349节点）聚合模式下3D图应展示模块级架构信息。

## 验收项（P0 = 必须，P1 = 建议）

---

### 1. 项目分几块？（P0）

**标准**：每个聚合节点（模块）有长期可见的名称标签
- 格式：`模块名 (N)` — N为模块内节点数
- 字体≥14px，白色粗体，有文字阴影
- 不受 highDensity 模式影响
- **验收**：打开 Hermes Agent 页面，看到 `gateway (34)`、`agent (99)`、`plugins (87)` 等标签

---

### 2. 核心是什么？（P1）

**标准**：枢纽模块（连接数最高的模块）视觉突出
- 节点尺寸比其他模块大30%
- 金色边框或发光
- **验收**：3秒内看出哪个是核心模块

---

### 3. 数据怎么流？（P0）

**标准**：跨模块边束可见
- 聚合后模块间的连线数 ≥ 50条（基于3349节点/125模块的估算）
- 边束颜色映射：data=#60A5FA(蓝)、control=#3B82F6(深蓝)、event=#34D399(绿)
- 边束宽度与 bundleCount 挂钩（越粗连接越多）
- hover 边束显示 bundleCount 数值
- **验收**：打开页面能看到模块之间有颜色的连线。分辨出蓝色和绿色管道。hover 显示 bundleCount。

---

### 4. 哪些是一伙的？（P0）

**标准**：单击聚合节点 → 左侧模块详情面板显示
- 面板内容：模块名、成员节点数、层级分布、模块间连接统计
- 诊断文本：summary + detail（如有）
- 优化建议列表（如有）
- 成员节点列表（可单击跳转）
- **验收**：单击 `gateway` 聚合节点，左面板显示"34个成员节点"、层级分布、连接数

---

### 5. 整体能干什么？（P0）

**标准**：全局诊断面板可见（底部居中）
- 评分（如 5.1/10）
- 问题清单
- 优化建议
- **验收**：页面加载后底部自动显示评分和问题清单

---

### 6. 交互逻辑（P0）

**标准**：三次操作闭环
- 单击聚合节点 → 模块详情面板打开（左栏）
- 双击聚合节点 → 子节点展开可见 + 子节点间连线出现 + 详情面板更新为成员信息
- 双击空白处 → 子节点折叠 + 面板关闭
- **验收**：三次操作完整闭环，节点不消失

---

### 7. 降级标准（P1）

**标准**：无 agentDiagnosis 数据时
- 聚合节点仍显示标签和模块名，颜色用默认灰色
- 详情面板显示"诊断数据未生成，请运行 npm run diagnose"
- **验收**：删除诊断文件后刷新，页面不白屏

---

## 优先级
**P0**（信息完整性必须）：1(标签) + 3(连线) + 4(详情面板) + 5(全局诊断) + 6(交互)
**P1**（视觉增强）：2(枢纽高亮) + 7(降级)
