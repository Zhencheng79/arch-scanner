# 性能优化方向方案 v1

## 背景
v0.1.53 信息展示完整但帧数极低（拖拽时几帧），0边线显示，聚合节点展开/折叠失效。

## 两个优化方向

### 方向A：纯渲染优化 — InstancedMesh + 帧率控制
**思路**：不改变展示形式，只优化渲染管线

- **InstancedMesh**：3349个文件节点合并为1个InstancedMesh + 每个节点的transform矩阵
  - draw call从3349→1
  - 需要处理多颜色（per-instance color）
  - 需要处理点击交互（raycaster支持InstancedMesh）
- **连线优化**：376条边束全部合并为1个BufferGeometry（LineSegments）
  - draw call从376→1
- **帧率控制**：requestAnimationFrame降帧（移动端30fps，静止60fps）
- **CSS2D裁剪**：视野外的标签不渲染
- **工作量**：约2-3小时
- **效果预期**：从2fps提升到30-60fps

### 方向B：表现形式精简 — 两级视图（模块级 + 展开级）
**思路**：不追求一次性渲染所有东西，改为按需展示

- **默认视图**：只显示模块级聚合节点（不移入子节点），不显示文件级节点
  - 节点数从130→约50（只保留模块GroupNode）
  - 边数从376→模块间粗管道数量（约30-50条）
- **展开视图**：双击模块节点才显示内部文件节点和内部连线
- **两级切换**：展开/折叠不消失，动画过渡
- **工作量**：约1-2小时
- **效果预期**：默认状态下30fps以上，展开时降帧但可控

### 方向C：两者结合（推荐）
先做方向B（1-2小时，立竿见影），再做方向A（锦上添花）

## 推荐
方向B（表现形式精简）先做，因为：
1. 工作量小，见效快
2. 同时解决了"0边线"和"展开折叠失效"两个问题
3. 默认视图流畅了，主公才能继续测试其他功能
