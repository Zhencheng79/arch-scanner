## 一、AGENTS.md 修改提案

**当前约束**（AGENTS.md 第27行）：
> viewer.html 是单文件，所有代码内联，不要拆分成多文件

**提案修改为**：
> viewer.html 是单文件，所有代码内联，不要拆分成多文件。例外：当单文件超过 500KB 且功能拆分可显著提升可维护性时，可拆分 CSS 和独立 UI 层，但核心渲染逻辑（Three.js 场景构建）保留在 viewer.html 中。

**理由**：
1. viewer.html 已从最初~200KB 增长到 756KB，超过3倍
2. 功能拆分只涉及 CSS 和 UI 层（不涉及 Three.js 核心渲染）
3. 拆分后入口文件仍保持 ~200KB（CSS+UI层抽出），降低了单个文件的认知负载
4. 接入模块化后未来新增功能的开发效率更高
5. 不影响离线可用性——多文件在本地加载速度差异可忽略

## 二、执行顺序（修正为全串行）

```
Step 1: force-layout 功能同步
  └── 在现有单文件结构上做，不涉及文件拆分
        ↓
Step 2: 代码拆分（在 node-spread 上做）
  └── 抽出 CSS + UI 层
        ↓
Step 3: 拆分结构同步到 force-layout
  └── 在 Step1 完成的基础上，同步 Step2 的文件结构
        ↓
Step 4: 双分支验收
  └── 自举 + 外部项目，量化对比
```

**为什么 Step3 在 Step1 之后？**
- Step1 先同步功能（单文件形式），改动集中在 viewer.html 内部，复杂度最低
- Step2 改文件结构，只在 node-spread 上做，不影响 Step1 的稳定性
- Step3 将拆好的结构同步到 force-layout，此时 force-layout 功能已与 node-spread 一致，只需文件结构调整

## 五、核心算法 Mock 测试

### 测试目标
在不打开浏览器的情况下，通过 Node.js 验证核心逻辑的正确性。

### 测试内容

| 测试 | 函数 | 输入 | 预期输出 |
|------|------|------|---------|
| 模块检测 | detectModule() | `"db--user-service"` | `"db"` |
| 模块检测-兜底 | detectModule() | `"random-thing"` | `"other"` |
| 层级解析 | resolveLayer() | `{layer:"business"}` | `"business"` |
| 连接流向格式化 | — | from→to 对的连接数据 | 方向正确 |
| 节点聚合 | — | 20个节点的输入 | 聚合后的分组数正确 |

### 实现方式
- 在 `packages/3d-monitor/tests/` 目录下创建 `logic.test.js`
- 将 viewer.html 中的纯函数部分提取为 Node.js 可引用的模块
- 运行方式：`node tests/logic.test.js`
- 不测试 Three.js 渲染（无法在 Node.js 中运行）
