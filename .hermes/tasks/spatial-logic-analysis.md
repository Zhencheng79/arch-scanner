# 3d-monitor 空间逻辑分析 — 为什么空间关系不成立

## 一、当前布局逻辑（问题根源）

```
逐节点分配位置（computeLayout）
  → 按 layer 排 Y
  → 按 group 排 X
  → 随机散布 Z
  ↓
模块台面包裹节点范围（被动生成）
  → minX/maxX/minZ/maxZ + padding
  → 台面是"事后框出来的"，不是"事前规划好的"
```

**核心矛盾**：模块是空间组织的核心单位，但布局算法不把模块当作第一优先级。

### 具体问题

| 问题 | 表现 | 根因 |
|------|------|------|
| **台面大小被动** | 台面包不住节点，或者比节点大很多，不自然 | 台面尺寸 = 节点范围+padding，不是根据模块成员数量规划的 |
| **模块间间距不足** | 不同模块的台面靠得太近或Z轴重叠 | 布局按layer/group分，不是按module分 |
| **台面Y位置不匹配** | 台面和节点在Y轴上有偏移 | 台面Y = minY-1.8，但节点Y按layer排，可能出现节点悬空 |
| **other模块无台面** | 26个other节点散落在各层，没有视觉归属 | other没有台面，也没有分组视觉提示 |
| **模块间管道定位** | 从节点到节点，不是从台面到台面 | 跨模块管道应该从源模块台面边缘到目标模块台面边缘 |

---

## 二、改进方向（模块优先布局）

```
先确定模块台面（事前规划）
  → 根据模块成员数量和层级确定台面位置和大小
  → 台面之间有足够的间距
  → 节点在台面范围内散布
  ↓
渲染（主动表达）
  → 台面 + 节点模块色边框
  → 跨模块粗管道从台面边缘到台面边缘
  → other节点单独处理
```

### 关键设计变更

**1. 布局改为以模块为核心**

当前（问题）：
```
nodes → computeLayout → positions → moduleLayoutInfo（被动）
```

改为：
```
nodes → detectModules → modulePositions → nodesPlaceInModules → moduleLayoutInfo
```

**2. 台面变成"3D房间"而非"2D背景板"**

- 每个模块一个独立的3D区域（像房间/隔间）
- 台面是地面，节点站在地面上
- 台面之间有一定间距，视觉上分开

**3. 跨模块管道**

- 从源模块台面边缘出发，到目标模块台面边缘
- 不经过中间节点

**4. "other"节点处理**

- 项目根目录的松散文件（README、package.json、vite.config等）本身就没有清晰的模块归属
- 建议：放在一个独立的"项目根目录"区域，不参与模块布局

---

## 三、需要讨论的问题

1. **布局算法的改动量**：computeLayout 重写 vs 在现有基础上调整
2. **"other"节点的视觉处理**：单独区域？散落在背景中？还是缩小尺寸表示"非核心"？
3. **模块台面形状**：保持扁平矩形？还是改为有厚度的3D平台？
4. **跨模块管道路径**：从台面边缘到台面边缘的曲线路径如何计算？
