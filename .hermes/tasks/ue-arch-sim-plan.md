# 【方案C】UE 架构模拟器 — 与 arch-scanner 的互补融合方案

> 文档版本: v1.0
> 状态: 待军师审阅
> 关联项目: arch-scanner (port-tag-tool + 3d-monitor)

---

## 一、战略意图：为什么要有 UE 方案

### 1.1 arch-scanner 的定位（不变）

```
port-tag-tool → JSON → 3d-monitor（Three.js 浏览器）
角色：轻量级"看架构"工具
核心价值：打开浏览器即看，秒级加载，零部署
目标用户：所有人（含非技术人员）
```

**这是底线，不能动。** 任何 UE 方案都不能削弱这个核心。

### 1.2 UE 方案的定位（新增）

```
port-tag-tool → JSON → UE 架构模拟器（Unreal Engine 5.8）
角色：沉浸式"玩架构"平台
核心价值：交互模拟、动态演示、架构可视化叙事
目标用户：架构评审会议 / 产品演示 / 培训场景
```

**核心差异：看 vs 玩**

| 维度 | 3d-monitor（看） | UE模拟器（玩） |
|------|-----------------|---------------|
| 加载速度 | 秒级 | ~1-2分钟（编辑器启动） |
| 部署 | 浏览器，零依赖 | 需 UE 5.8+（60GB） |
| 交互 | 旋转/缩放/点击 | 拖拽节点、实时连线、动态模拟 |
| 叙事 | 静态拓扑图 | 可编排的架构演示 |
| 适用场景 | 日常查看 | 评审/演示/培训 |

### 1.3 两者关系：互补而非替代

```
数据同源（port-tag-tool JSON）
        ├── 3d-monitor: 快速看，日常用
        └── UE模拟器: 沉浸玩，特定场景用
```

**数据层完全共享**，渲染层各自独立。改 port-tag-tool 的扫描规则，两个渲染器都受益。

## 三、分阶段实施方案

### 阶段 0：基础准备（UE 环境搭建）
**前置条件，先于一切**

| 步骤 | 内容 | 耗时 |
|------|------|------|
| 0.1 | 安装 Epic Games Launcher | ~5min |
| 0.2 | 安装 UE 5.8+（~60GB下载+安装） | ~2-4h（后台） |
| 0.3 | 创建空白 UE 项目 + 启用 Unreal MCP 插件 | ~15min |
| 0.4 | Hermes 连接 UE MCP（hermes mcp 注册） | ~5min |
| 0.5 | 验证：Hermes 通过 MCP 在 UE 场景创建 Actor | ~5min |

**不依赖 arch-scanner 进度，可以随时开始。**

---

### 阶段 1：数据桥接（port-tag-tool → UE）
**把 arch-scanner 的 JSON 变成 UE 场景**

#### 1.1 JSON 加载器
- 编写 UE Python 脚本或蓝图工具，读取 port-tag-tool 输出的 JSON
- 解析 `nodes` → 在 UE 场景中生成对应 Actor（Box/Sphere + Label）
- 解析 `connections` → 生成连线（Spline/LineComponent）
- 解析 `ports` → 生成端口标记
- 解析 `tags` → 颜色/标签映射

#### 1.2 写入新 MCP 工具
在 3d-monitor 的 mcp-server.js 中新增工具：
- `mcp_tool_load_arch_json` — 读取 JSON 文件，返回结构化数据
- 或直接在 UE 端写一个 Python MCP Server 来处理

#### 1.3 输出
- ✅ 在 UE 编辑器中看到 arch-scanner 扫描出的项目结构
- ✅ 与 3d-monitor 展示相同的拓扑数据

**数据桥接工具 1 人天，完成后永久复用。**

---

### 阶段 2：交互增强（UE 场景互动）
**让"静态架构图"变成"可交互的架构模型"**

#### 2.1 基础交互
- 单击节点 → 高亮 + 显示详情
- 拖拽节点 → 重新布局（UE 物理引擎）
- 双击节点 → 聚焦 + 展开子节点
- 鼠标悬停 → 显示端口/连接信息

#### 2.2 视觉增强
- Lumen 全局光照 → 架构图更有层次感
- Nanite 高精度节点 → 支持大量节点不降性能
- MegaLights 动态光效 → 数据流可视化光效

#### 2.3 层级管理
- 分层显示/隐藏（按 layer 字段）
- 搜索定位节点
- 书签/预设视角

**与 3d-monitor 的关系：交互方式 UE 重做，不复用 Three.js 代码。**

---

### 阶段 3：动态模拟（UE 独有能力）
**这是 3d-monitor 做不到、UE 独有的价值**

#### 3.1 数据流动画
- 连接线流动光点（类似网络流量）
- 热力图模式：按调用频率/数据量着色
- 故障注入演示：断掉某节点连线，观察整体影响

#### 3.2 架构叙事
- 预设演示路径（镜头沿架构层级移动）
- 按时间线展示架构演进（v1.0 → v2.0 → v3.0）
- 可分步讲解：先展示外层 → 再展示内部 → 最后展示数据流

#### 3.3 多人评审（UE 的 Pixel Streaming）
- 通过 Pixel Streaming 把场景推送到浏览器
- 参会者无需安装 UE，打开网页即可观看
- 评审者可在场景中添加标注/意见

**这是 UE 方案的真正价值所在，也是未来两年内 Three.js 很难做到的事情。**

---

### 阶段 4：工具链闭环（MCP 互联）
**Hermes 通过 MCP 同时操控 arch-scanner 和 UE**

```
Hermes（赵公明）
  ├── MCP → port-tag-tool: 扫描项目
  ├── MCP → 3d-monitor: 轻量展示
  └── MCP → UE: 沉浸式展示 + 动态模拟
```

#### 4.1 Hermes 自动工作流
- `"扫描这个项目"` → port-tag-tool 扫描 → JSON
- `"在浏览器看"` → 3d-monitor 打开
- `"在 UE 里展示"` → UE 场景加载 JSON → 自动布局
- `"演示这个架构"` → 触发 UE 预设演示路径

#### 4.2 一键切换
- 3d-monitor 中点击"在 UE 中打开"按钮
- 自动启动 UE 编辑器（如果已安装）
- 加载当前架构数据到 UE

## 四、风险与权衡

### 4.1 硬件门槛
| 风险 | 影响 | 缓解 |
|------|------|------|
| iMac GPU 弱（Radeon Pro 580X） | 编辑器卡顿，Lumen/Nanite 不可用 | 使用 UE 的基础渲染模式，关闭高级特性 |
| 64GB 内存要求 | 大数据集项目可能内存不足 | 当前 32GB 够跑小项目，大项目需硬件升级 |

### 4.2 开发成本
| 项目 | 估算 |
|------|------|
| 阶段1 数据桥接 | 1-2 人天 |
| 阶段2 交互增强 | 3-5 人天 |
| 阶段3 动态模拟 | 5-10 人天 |
| 阶段4 工具链闭环 | 2-3 人天 |
| **总计** | **11-20 人天** |

### 4.3 维护成本
- UE 版本更新（每年大版本，插件 API 可能变化）
- 数据 schema 变动（port-tag-tool 升级后需要同步更新 UE 解析器）
- Three.js 和 UE 两边功能同步

## 六、方案C的"标准答案"式总结

> **用 Unreal Engine 为 arch-scanner 打开一个"沉浸式架构体验"的新维度。**
>
> arch-scanner 负责扫和轻量展示（浏览器，秒级），UE 负责沉浸式交互和动态模拟（需安装，分钟级）。
>
> 两者数据同源、渲染分离、场景互补。不替代，不覆盖，只扩展。
